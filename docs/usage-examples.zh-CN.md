# 最小使用案例

[English](./usage-examples.md) · **简体中文**

直接说明目标与边界。执行者只读取当前证据缺口需要的模块；小任务不必新建设计基线文档或通读全部资料。[合成按钮前后对照](./evaluation/results.md#1-mature-button-fixture)与[token演练](./evaluation/token-case/TASK.md)提供具体改动和验证限制；这些是合成场景，另有[三组公开项目源码案例](./examples/README.zh-CN.md)提供历史修复、固定证据及原许可。

## 仅修按钮按压反馈

```text
使用 $design-visual-interaction，只修这个按钮在操作中断后的按压反馈。
保留现有主题、动作和配置，检查共享消费者，只改必要的事件或样式。
说明哪些输入路径实际验证过。
```

先追踪组件与 token/theme 来源，按需选择按钮、动效、验证模块。核对正常释放、取消、失焦/禁用/离开及重新操作；动作仍由原输入系统触发。不得顺带更换材质、重写输入框架。源码或事件替身通过，不能写成真实手势或视觉通过。

## 仅修设置页信息层级

```text
使用 $design-visual-interaction，只整理这个设置页的入口和分组。
保留现有选项、保存值、默认值及不同时间参数的含义。
先从源码核对路由与父子依赖，再改必要的页面构造。
```

复用已有设置组件，必要时兼容旧入口；业务策略保留原归属。检查父开关关闭/恢复、配置保留、迟到回调、返回，以及受影响的语言/字号。移动入口不授权改业务调度或其他 Dock 栏目。

## 只审计，不改代码

```text
使用 $design-visual-interaction 审查这个页面，不修改文件。
对重要发现说明：源码或观察证据、用户影响、已确认根因或假设、
最小建议和待补验证。允许得出无需修改的结论。
```

交付诊断和建议，不实施、不顺带格式化，也不以“准备补丁”为由修改工程。截图、用户报告和亲自检查的源码分别标记；静态审查可带运行缺口结束。

## 冲突处理示例

项目已认可实色表面和现有 token，用户要求“让这个按钮更现代一点”，不构成试验液态玻璃或另建主题的授权。先复用既有按压参数，限制修改范围。用户明确要求玻璃试验时，再隔离目标组件、保留语义/焦点/对比要求、沿用主题并约定原材质回退。平台建议是需要评估的证据，不自动覆盖用户认可决策；只有无法由请求与工程解决的关键冲突才需要进一步询问。

## 为什么只读少量模块

缺少上下文时才补基线或平台模块；组件模块解决具体问题，验证模块决定对应证据。关联链接不表示递归加载。见[模块关系图](./module-routing.md)。
