# Changelog

[简体中文](./CHANGELOG.zh-CN.md)

## 0.3.1 — 2026-10-29

- Make concise interface copy a shared baseline: remove explanations and repeated hints unrelated to the user's task, shorten labels, and use recognizable symbols when their meaning is clear.
- Distinguish missing values from real zero; retain actionable errors, permission effects, irreversible consequences, privacy information, essential status and accessible names. Respect explicit user choices and disclose reduced visible context.
- Check affected states, languages, text scaling, narrow layouts and shared consumers; static checks do not establish visual or assistive-technology acceptance.

## 0.3.0 — 2026-10-16

### Changes

- Make source-based token/theme extraction operational; require reuse of the existing system and prohibit a parallel one. Add a short visual-language preservation check.
- Define static, event, rendered and real-device evidence separately, with change-specific checks and explicit device gates. Missing devices produce bounded candidate results, not false acceptance.
- Restrict liquid glass to explicitly requested experiments or fixes to components already using it; retain existing materials by default.
- Add three scoped usage examples, a conflict example and module-routing diagram. Make the README audit example explicitly read-only.
- Recommend the version-pinned `v0.3.0` install; preserve separate companion ownership and MIT licensing.

### Verified within a stated scope

- Added three real public-source historical cases from React Aria, Radix and Flutter, with pinned commit/parent/file locations and original licenses. Two JS excerpts have four bounded contracts each; a Dart excerpt has three static precedence checks. Old counterexamples fail, later excerpts pass. Full upstream suites, browser input and Flutter rendering were not run.

- Isolated button-token task: a fresh agent reused existing scale/duration/easing and reduced-motion tokens, changed only two declarations, and reported the unavailable browser accurately. This is one bounded exercise, not a benchmark.
- Release integrity and existing regression/event checks: see [validation record](./VALIDATION.md).

### Still being observed

- Token extraction robustness across larger stacks; universal stability of the new routing wording; cross-model repeatability and real-world effectiveness.
- Real-device appearance, physical/native input, assistive technology, GPU/power cost and glass fallback quality. No device-accepted before/after screenshots are claimed.

## 0.2.0 — 2026-10-16

- Reviewed six existing open-source design-skill projects and recorded exact sources, licenses and adoption boundaries.
- Added composition/hierarchy and platform-adaptation modules without a runtime dependency.
- Distinguished audit, critique, focused repair and new-direction work; clarified global rules and scoped exceptions.
- Improved evidence-aware findings, detector false-positive checks, numeric layout and recovery copy.
- Added two bounded forward exercises and a guarded upstream documentation-correction proposal; the upstream PR has not been submitted.

## 0.1.0 — 2026-10-16

- First experimental release: a small entrypoint with on-demand component modules.
- Ten references covering project baselines, controls, layout, settings, motion, materials and verification.
- Optional liquid-glass direction; no automatic reskin or mandatory companion dependency.
- English-default repository documentation with a Chinese entry, MIT license, original schematic and repository validation.
- Explicit boundaries for shared-component changes, no-change conclusions and unverified rendering.
