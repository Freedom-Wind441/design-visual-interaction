# 验证与交付

## 适用条件

实施后的验收或制定验证方案。按风险选检查，不为小修改新增镜像实现的测试。

## 目标与约束

验证用户目标、功能、配置和真实影响面。证据对应版本、环境与路径，分别记录静态、构建、事件模型、运行渲染和实机体验。

## 依赖与联动

由所选组件模块提供状态边界；共享 token/处理器检查其他消费者。结构迁移另做架构验收，不凭搜索或目录证明无回归。

## 实施

### 按改动选择层级

静态审查可以确认源码事实；运行层级按下面的触发条件补齐，不能用高数量的低层测试抵消缺失的设备证据。

| 层级 | 可操作检查 | 能支持的结论与边界 |
| --- | --- | --- |
| 静态 | 查 token/主题覆盖、文案/角色/状态、点击区域与遮挡候选、焦点声明/顺序；按目标平台规则检查对比候选 | 可确认确定的逻辑/配置问题；透明合成、字体实际边界和动态焦点仍需运行 |
| 构建/事件 | 编译；执行正常/取消/禁用/离开/重入；核对动作次数、保存/回滚及回调时序 | 证明覆盖的契约；替身不证明原生派发、像素或手感 |
| 运行渲染/交互 | 同条件 before/after；明暗、长内容、目标字号；点击/拖动/键盘，动态焦点遍历及减少动态效果 | 仅对实际运行的栈/环境下结论；截图不证明反馈时机或输入是否被阻挡 |
| 目标实机 | 记录设备/OS/版本及主题/字号；操作真实输入和中断，核对平台材质、辅助技术与性能 | 可支持该设备与路径；不外推所有平台和硬件 |

| 改动类型 | 最少应做的检查 | 必须升级到目标实机的条件 |
| --- | --- | --- |
| 仅审查/方案，不改代码 | 静态定位与有界结论；仅有截图时根因保持假设 | 不要求为出方案启动设备；方案中的运行结论不得标已验证 |
| 局部文案/声明、无运行效果声明 | 核对语义、调用点、配置及范围；实施时使用已有适当构建检查 | 出现截断/布局问题或验收要求真实显示时，增加渲染；设备专有问题再上实机 |
| 样式/布局/token | 代表消费者、对比/目标区域候选、同条件真实渲染；长文案/字号/明暗按影响选择 | 平台字体、窗口/安全区、OEM 布局或触摸命中依赖设备时 |
| 按压/手势/动效 | down→正常完成、cancel、移出、多指、失焦、禁用、detach、快速重入；反馈时机、动作次数、输入连续性 | 原生派发、触觉、OEM 反馈、系统手势、手感或帧率结论 |
| 设置/导航/能力 | 父开关关闭/恢复、持久化、偏好与有效值、能力未知及回退、迟到提交、返回栈/深链、焦点顺序与屏幕阅读语义 | 真实辅助技术、系统返回/边缘手势、覆盖升级或系统/OEM 能力验收 |
| 材质/性能 | 实际合成、复杂背景、减少透明/动态效果回退、代表消费者 | 引入/改变原生模糊、GPU/折射路径，或宣称性能/耗电改善时 |

实机门槛是上述结论的证据要求，不是自动阻塞一切交付的许可门槛。环境缺失时完成可做部分，列出具体未验收动作；交付候选修复，不宣称设备问题已解决。跨平台改动在每个受影响渲染栈取代表环境；仅实际受影响的平台需要扩展。

静态对比度可按确定的有效前/背景计算并记录采用的规则；若背景依赖合成或动态采样，静态数值只是候选。点击区域需核对视觉范围、命中范围与裁剪/覆盖，焦点需区分声明顺序与运行遍历；不将样式扫描等同全面可访问性通过。

先复现或界定问题，再用相同条件核验；行为检查优先用已有测试。截图不能证明交互/配置，录屏不能独立证明全部路径。缺运行环境时完成可做检查并说明缺口，不以模型自评替代证据。

审查发现简记“位置与证据 → 用户影响 → 根因或假设 → 最小处理 → 验证方式”。优先级按任务阻断、显著困难、局部不便、纯表现建议区分；证据状态另记已复现、静态确认或待验证，不能以影响严重替代证据充分。已有正确模式与合理例外也应保留，不凑问题数量或用主观总分宣布品质。

自动检查器、搜索与样式扫描先核对命中是否适用，再形成发现。其覆盖的是已实现规则，不能由“无命中”推出整体可用、审美优秀或 WCAG 全面符合；设计评议另检查任务层级、内容组织与真实使用路径。先集中检查代表条件并修复发现，只有新增改动、失败或未知项才扩大/重复检查，避免无终点的润色循环。

视觉参考注明来源、许可/授权、平台/版本、观察点和认可状态；示意/生成图不作实机证据，不虚构截图或用户认可。

## 验收

简要说明实际改动、根因/影响面、通过的检查及未知项，保留必要命令、截图或日志及代码版本。变更后重核相关证据。

允许“无需修改”“静态通过，渲染待验证”。证据覆盖约定范围才称该范围通过；不保证跨项目提升、零回归或固定 token 节省。
