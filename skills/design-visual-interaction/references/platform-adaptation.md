# 平台适配

## 适用条件

平台或实现栈不明确、跨平台扩展，或准备将外部 Web/原生规范用于当前项目。已经明确平台的局部修改直接使用已有适配，不重复调查全部技术栈。

## 目标与约束

复用任务语义与设计意图，按宿主实现交互和渲染；不承诺同一代码、单位、材质 API 或审查工具可跨平台直接运行。品牌一致不要求所有平台像素相同。

## 依赖与联动

从实际构建、依赖和入口识别技术栈；混合应用逐表面辨别 WebView、原生或跨平台渲染层。边界、适配器和能力状态由架构技能协作，具体体验由组件模块约束。

## 实施

| 关注项 | Web 表面 | 原生 / 桌面 / 跨平台表面 |
| --- | --- | --- |
| 布局与缩放 | CSS、浏览器缩放、视口和安全区域 | 框架布局、逻辑单位、系统文字缩放、窗口与键盘区域 |
| 可访问语义 | 优先语义 HTML，必要时补 ARIA | 平台/框架的名称、角色、状态和辅助技术接口 |
| 输入与导航 | 原生链接/按钮、浏览器历史、键鼠与触摸 | 系统返回/手势、焦点、快捷键与平台控件行为 |
| 主题与材质 | 实际 CSS 支持、合成与回退 | 系统 API、版本/能力、原生主题及可读降级 |
| 验证 | 目标浏览器渲染和实际输入；静态工具只作补充 | 平台构建、模拟器/目标设备、框架工具和对应辅助技术 |

规范数值必须附平台、单位、版本/等级与例外。Web 的 CSS px 不能当作 Android dp、文字 sp 或 Apple pt；WCAG AA 的最低条件、AAA 的增强条件与项目舒适目标分别记录，不混为一个“通用最小值”。原生要求核对当前官方说明，不凭记忆硬套 Web 阈值。

优先项目已有设计系统和原生/成熟基础控件；只有缺少能力且成本合理时才定制。自定义控件需补齐其状态、焦点、取消及辅助操作，不能只画外观。

外部工具按能力接入，不为局部任务引入浏览器引擎、数据库或固定服务依赖。未执行的工具只列为可选验证路径，不能说已完成其检查；浏览器规则命中不证明原生应用有同一问题。

## 验收

每个具体实现建议可追溯到实际渲染层；单位、语义、输入与验证环境匹配。保留跨平台合理差异，明确尚不支持或未知能力，无“改名即适配”或“Web 静态检查即实机通过”。
