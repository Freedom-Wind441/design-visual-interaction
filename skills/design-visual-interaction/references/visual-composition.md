# 构图与视觉层级

## 适用条件

新页面或获授权的重设计，以及“平淡、拥挤、主次不明、信息难找”等设计评议。仅修事件或组件参数时不默认读取；已有成熟方向时按其规则检查。

## 目标与约束

使用户先看见完成任务所需的信息，再理解关系并找到操作。视觉个性来自产品任务、内容与已认可方向；不为区别于模板而牺牲平台习惯、信息密度或可用性。系统字体、卡片、圆角、渐变和玻璃均非天然错误。

## 依赖与联动

缺少方向时读项目基线，具体字号/换行读排版，色彩/层次读材质；只联动涉及的部分。代码可揭示结构与参数，真实感知仍需渲染证据。

## 实施

1. 用一句话写清当前表面的首要任务及信息重点。例如分析界面先支持比较与异常定位，而不是默认放一个巨大的装饰数字。记录主任务、次任务与暂不展开的信息。
2. 对新方向选少量相关维度：信息密度、强调强度、形状/材质、文字气质与动效克制程度；用布局和参数解释“简洁、轻盈”等词。已有方向则复用。只有方向不明确且比较能改变决策时才提出 2–3 个备选，不给局部修复强加选型流程。
3. 建立主次：用适当的空间、大小、字重、位置或对比突出重点，不让所有信息同时争抢。辅助内容减弱但仍可读；主要/次要/危险操作保留语义差异。
4. 依据任务组织信息：组内关系紧密、组间边界清楚；相关数据靠近，比较对象对齐。卡片用于实际分组、操作或独立内容，不因模板而拆碎一段连续任务；移除容器前检查其是否承担交互/语义作用。
5. 按内容选密度与节奏。交易表格和阅读页面可用不同留白，不能通过大量空白掩盖缺信息。窄窗口调整排列与优先级，保留核心数据和完整内容入口。
6. 少量有理由的特征即可建立识别，不要求每个组件都独特。品牌色、装饰、图像和动效需要承担明确角色；序号只用于有顺序的信息。保留有用说明，删除重复标签与无信息的装饰文案。
7. 使用真实或明确标注的代表内容试排。查看整体与局部：主任务能否辨认，关键比较是否容易，操作是否可预测，异常/空状态是否有下一步；截图条件一致后再比较。

## 验收

将观察分为可验证缺陷、设计判断和偏好建议；分别给出依据。检查信息重点、分组、密度、视觉节奏与状态语义，不用“更高级”或总分替代具体结果。没有运行画面时只交付待验证的方案；已有良好层级时允许保留。
